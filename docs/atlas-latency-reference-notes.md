## Official MongoDB facts

- **Free/M0:** 10 GB inbound and 10 GB outbound per rolling seven days; 100 read/write operations per second. Exceeding either limit throttles network speed and introduces a one-second cooldown per connection; queued work can wait longer. Metrics are limited to Connections, Logical Size, Network and Opscounter. Logs and Performance Advisor are unavailable. [Free cluster limits](https://www.mongodb.com/docs/atlas/reference/free-shared-limitations/).
- **Flex:** 500 operations per second, followed by a sub-second per-connection cooldown above that ceiling; queues can still wait longer than a second. [Flex limitations](https://www.mongodb.com/docs/atlas/reference/flex-limitations/). Flex includes unlimited data transfer in its base price, so the M0 seven-day allowance must not be applied to Flex. [Flex usage and costs](https://www.mongodb.com/docs/atlas/billing/atlas-flex-costs/).
- **Dedicated:** M10+ deploys each `mongod` process to its own instance and supports Performance Advisor. That removes the specific Free shared-tier constraints, but does not prove sufficient CPU, disk or bandwidth for a workload. [Manage clusters](https://www.mongodb.com/docs/atlas/manage-clusters/).
- **Tier and region:** Atlas's project Clusters view displays Cluster Tier and Region. `atlas clusters describe` is a read-only administrative alternative with the corresponding Atlas access. A database URI identifies connectivity, not the authoritative subscription tier. [Deployment details](https://www.mongodb.com/docs/atlas/manage-database-deployments/), [Atlas CLI procedure](https://www.mongodb.com/docs/atlas/manage-clusters/).
- **Database-command caveat:** `hello` may contain member tags; Atlas pre-defined provider/region tags are an M10+ feature. Their absence does not identify M0 versus Flex. [Atlas replica-set tags](https://www.mongodb.com/docs/atlas/reference/replica-set-tags/). DNS/IP geolocation remains an inference and should not replace Atlas configuration.
- **Metrics:** Network charts report average physical bytes or requests per second over the selected sample period. Host metric names include `NETWORK_BYTES_IN`, `NETWORK_BYTES_OUT`, `NETWORK_NUM_REQUESTS` and `OPCOUNTER_GETMORE`. [Project metrics](https://www.mongodb.com/docs/atlas/review-all-cluster-metrics/), [Host metrics](https://www.mongodb.com/docs/atlas/reference/alert-host-metrics/). Use network history and operations together with measured command/batch timing. These references do not document a customer-visible M0 boolean that definitively confirms network throttling; do not label it confirmed solely from a slow request.
- **Explain is server work, not end-to-end latency:** `executionTimeMillis` includes plan selection and execution, explicitly excludes sending results to the client, and can differ from actual cached-plan execution. `explain` ignores the plan cache. `totalDocsExamined` counts examinations, including repeated examinations; `$lookup` statistics report index use and collection scans. [Explain results](https://www.mongodb.com/docs/manual/reference/explain-results/).

## Checking the actual rolling transfer allowance

Follow-up checked against current official documentation: no public M0 field was found that reports exact internal rolling-seven-day allowance consumption or a definitive transfer-throttled state. The following paths expose observations rather than the limiter's accounting:

1. **Atlas UI:** Clusters → click the cluster name → Metrics → Network. Set Zoom to one week, or use Current Display for the exact last seven days. Granularity controls sampling; Toggle Members controls scope where available. Hover a chart and open its info icon for the Chart Info modal, which lists series and supported operations. [Official chart controls](https://www.mongodb.com/docs/atlas/review-replica-set-metrics/). The `bytesOut` series is an average rate of physical bytes per second **after wire compression**, not a cumulative quota total. [Metric definition](https://www.mongodb.com/docs/atlas/review-available-metrics/).
2. **Read-only Admin API:** the documented generic process-metrics endpoint is `GET /api/atlas/v2/groups/{groupId}/processes/{processId}/measurements`, with `period=P7D`, `granularity=PT1H`, and repeated `m=NETWORK_BYTES_OUT` / `m=NETWORK_BYTES_IN`. It requires Project Read Only. Enumerate process identities using the documented process-list endpoint rather than assuming which hostname represents the entire cluster. The endpoint returns measurement time series; its published fields include no weekly network quota total or transfer-throttle flag. Availability of an individual measurement depends on process/tier, and M0 access was not tested here. [Current API reference](https://www.mongodb.com/docs/api/doc/atlas-admin-api-v2/operation/operation-getgroupprocessmeasurements).
3. **Interpretation:** integrating observed byte-rate samples over the window estimates actual transfer. It requires handling missing samples, correct member scope and sample units. It does not establish that this total equals the internal Free-tier allowance accounting. Do not substitute the uncompressed refresh payload estimate for measured seven-day wire traffic.
4. **Operation Throttling chart:** its name is insufficient to establish Free-tier network throttling. The Admin API's metric enum includes `OPERATION_THROTTLING_REJECTED_OPERATIONS`, not a weekly transfer-allowance counter. MongoDB's Ops Manager chart documentation defines rejected/killed series in terms of query rejection filters and timeouts. [Official chart definition](https://www.mongodb.com/docs/ops-manager/current/review-available-metrics/). Atlas also uses Operation Throttling when testing workload rejection on M30+/MongoDB 9.0+. [Atlas load-shedding definition](https://www.mongodb.com/docs/atlas/tutorial/test-resilience/test-load-shedding/). These mechanisms must not be treated as proof of the M0 transfer cooldown; inspect the live chart's own Chart Info.

If internal quota confirmation is needed, Atlas Basic support includes weekday chat through the bottom-right in-app chat icon. A suitable request is to confirm the cluster's rolling outbound byte accounting and whether network-transfer throttling was active at the measurement time. That is an external communication and was not sent as part of this read-only investigation. [Current support procedure](https://www.mongodb.com/docs/atlas/support/).

## Continuous catalog load

The deployed implementation and current workspace both warm catalogs before starting HTTP serving and refresh them every **15 seconds**, regardless of user traffic. There are seven distinct cached parts: two relation identity scans, Spanish word metadata/text, German word text, Spanish phrase metadata/text, German phrase text, and ready German-to-Spanish grammar surfaces. Shared in-flight cache loads deduplicate overlapping callers, so this is seven distinct queries per completed refresh cycle, not the sum of every call site.

Sources: [startup](</Users/kevin/Desktop/kev/German Gramatic/german-gramatic-api/src/index.ts:36>), [refresh timer and calls](</Users/kevin/Desktop/kev/German Gramatic/german-gramatic-api/src/features/progress/studyLoading.ts:154>), [relation scans](</Users/kevin/Desktop/kev/German Gramatic/german-gramatic-api/src/features/progress/studyLoading.ts:145>), [word/phrase projections](</Users/kevin/Desktop/kev/German Gramatic/german-gramatic-api/src/features/progress/studyTextCatalog.ts:7>), [grammar surface scan](</Users/kevin/Desktop/kev/German Gramatic/german-gramatic-api/src/features/phrases/phraseGrammarCatalog.ts:7>), [single-flight refresh](</Users/kevin/Desktop/kev/German Gramatic/german-gramatic-api/src/features/progress/catalogSummaryCache.ts:42>).

Arithmetic inference: 15 seconds gives 5,760 cycles/day or 40,320/week per continuously running API process. A combined uncompressed payload of roughly 248 KB/cycle would already equal 10 billion bytes/week. This is an estimate, not observed quota usage: actual wire compression, refresh failures/overlap, uptime and replica traffic affect measured transfer. Additional API processes multiply the reads. The baseline seven finds alone average approximately 0.47 commands/second before `getMore`; that is a transfer-volume concern, not evidence of reaching the 100 operations/second ceiling.

The cache's hard TTL is 30 seconds. Fresh reads reuse the prior generation; once expired, a read waits for an in-flight replacement. If refresh takes more than 30 seconds, a user request can inherit that delay. Cold process startup also waits for all seven parts. [TTL and wait behavior](</Users/kevin/Desktop/kev/German Gramatic/german-gramatic-api/src/features/progress/catalogSummaryCache.ts:6>).

The grammar source file is untracked in the current checkout but its present content matches the deployed revision; `git diff` alone reports it as deleted because it is absent from the index. No deployed timer/projection behavior difference was found.
