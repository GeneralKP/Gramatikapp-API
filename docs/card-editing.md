# Personal card editing — unreleased

Web and native practice and dictionary use the same account-owned editor. German, Spanish, Notes, Examples and five flags (red, orange, green, blue, purple, or clear) apply to the bilingual pair and both directions. Mistakes and next due date apply to the selected directional study card. Unstudied dictionary pairs support text and flags without creating progress; their editor explains why scheduling controls are absent.

`cardedits` stores only the personal pair overlay, flag and content revision. The shared catalog, reviewed `WORDS_ES_DE.study`, live source card identity and imported Anki archives remain intact. Changing an ordinary primary answer removes obsolete accepted alternatives. CLOZE prompts, answers and checking alternatives retain their source identity; Notes and Examples remain editable. Notes replace generated verb notes, including when cleared; the legacy noun article remains available.

The complete study response adds `edit: {relationId, version, flag}` and `failureVersion`, with one indexed bulk owner-overlay read. Notes and Examples remain inline, so opening the practice editor, flagging, Check and Reveal require no content request. Dictionary pages read overlays for their displayed IDs through authenticated, no-store `/api/card-edits/read` (at most 100). `/api/card-edits/editor` loads only the chosen owned direction when Edit opens. Reopening a pair with pending EDITs first reconciles those commands, avoiding reapplying a manual delta over an already committed server response after a lost acknowledgement.

`EDIT` uses the existing durable study journal: atomic localStorage records on web and immutable private files with small AsyncStorage pointers on native. Practice commits before updating the UI and uploads on completion, exit/hide or recovery. Dictionary commits locally and starts background synchronization immediately. Save failures retain the form, and ambiguous native publication retries the original identity. A refreshed/different practice target cannot silently change the date displayed when the editor opened. Changes are computed against that displayed target, so an unchanged mistake field cannot erase a concurrent failure. Scheduling snapshots preserve personal Notes and Examples, including simultaneous legacy text/date changes. Account changes reject stale callbacks and requests.

`/api/study/sync` still sends at most 100 ordered commands within the client's byte bound. Only changed fields are sent. A Mongo transaction commits the overlay, optional mistake adjustment, optional schedule change and `cardeditevents` receipt together. The unique owner/command receipt rejects identity reuse and makes lost acknowledgement replay harmless. Content CAS, directional ownership and optional schedule version checks occur before any write; conflicts roll back the entire command and retain it on the device. A conflicting edit blocks dependent edits for the pair even across directions. The explicit **Keep server changes (discard conflicting local edits)** action discards their dependent local schedules but retains genuine FAILURE commands.

Mistake adjustments are deltas against the freshly stored counter, clamped at zero. They increment `failureVersion` so client merges can preserve a deliberate decrease while still preserving concurrent ordinary failures. Historical failure IDs, imported failure history, review events and writing credit are not rewritten. Manual due changes preserve the existing phase, interval, ease, repetitions and history, clear temporary dates and the Undo pointer, and advance `scheduleVersion`. The card leaves the active session, preventing a later rating from replacing that date. A postponed NEW German-to-Spanish prerequisite buries its NEW Spanish-to-German follower until the chosen date; clients also derive this burial when a dictionary edit precedes a queue fetch.

`npm run test:card-edits` uses mocked Mongo responses and transaction rollback, without connecting to a database. It asserts complete API response fields, owner isolation, authentication, validation bounds, conflicts, directional/CLOZE behavior, manual scheduling, prerequisite burial and exactly-once retry. The existing loading contract suite remains unchanged apart from the deliberate new response metadata. Both client tests cover local-only editing, selected-direction state, storage failures, retry IDs, due-date handling and the five colors. Future flag-based practice filtering is not part of this release preparation.

No production deployment, mobile release or inventory refresh was performed for this feature. Backend and client releases must be coordinated when explicitly requested. The saved model is [database-model/index.html](database-model/index.html); its production snapshot counts and audit date are unchanged.
