How to read the model

Boxes are collections; the Practice & sync view also labels browser storage and the API boundary. Arrows show logical references, with the field name and cardinality shown when you select a box. Dashed boxes are the same collection repeated from another view.

  • 1 → N means one parent can have many child records.
  • N → 1 means many records can refer to one entry.
  • MongoDB does not enforce these references as SQL foreign keys. The app joins them using ObjectIds or Anki numeric IDs.

One word, two cards

WORDS_ES_DE links a Spanish entry to a German entry. userprogresses stores each user's study cards, including the German → Spanish and Spanish → German directions.

For imported cards, itemId identifies the card and relationId identifies its vocabulary pair. Native cards also use a relation; older records can use itemId as the relation ID.

Mistakes and reinforcement

failureIndex starts with the number of Anki “Again” answers. Each wrong Check or Revisit adds 1 atomically. An attempt ID prevents a network retry from adding the same mistake twice. Undo changes the schedule without erasing mistakes.

card difficulty = max(0,
failureIndex − writingReinforcementCredit)

word difficulty = sum of its
active cards' difficulty

A completed Writing check adds up to 0.25 credit to one card for each included word, once per exercise. Lifetime mistakes remain intact. Merely generating or reopening an exercise gives no credit.

Why so many collections?

Seven hold the bilingual catalog and surface translations, four hold accounts and scheduling, and five hold saved Reading/Writing exercises, checks and hints.

The extra four ANKI_* collections preserve the original import, notes, cards and review log. They are an archive for verification and recovery; daily practice uses userprogresses and reviewevents.

Empty attempt collections are expected: the API creates indexes before your first submission. No new collection was added for active difficulty.

Daily new-card allowance

users.settings.dailyNewCards is an optional 0–1000 card limit shared across categories and sessions. Existing accounts fall back to their imported default deck limit (or 20). A word normally uses two places, recognition before typing. If just one place remains (including a limit of 1), recognition can use it; the first typing card waits for the next available allowance. Unused allowances do not accumulate.

Blue counts remaining eligible new cards; red counts available learning/relearning cards; green counts due reviews. A rating can move new → learning, or graduate directly to review. Setting the limit to 0 pauses new cards only.

Fast local practice

At entry, the API provides cards, counts and a serialized studyState containing scheduler options and a deterministic seed. This is a derived API value, not a stored MongoDB field. The browser uses generated copies of the server scheduling, fuzz and calendar logic.

Typing/revealing stays local. Failed Check, rating and Previous card append durable, account-scoped commands to device storage. Counters and schedules update locally. Previous card appends an Undo command to restore the prior schedule and sibling availability, then clears feedback, typed answers and selected phrase tiles. It opens an unanswered card with a fresh attempt ID; earlier lifetime mistakes remain, and a new wrong answer records a separate mistake. New directions preserve recognition-before-typing order, including when the daily allowance ends between the two directions. Sibling burial and leech suspension also run locally; Previous card restores sibling availability.

Sync and recovery

Leaving or finishing practice triggers an authenticated batch; hiding/closing makes a bounded keepalive attempt. Mobile termination can skip callbacks, so unacknowledged commands survive and retry on next launch. If the app can load while the API is unavailable, practice can use cached cards; this does not add an offline installable app or service worker. Acknowledged changes are checkpointed into cached cards and counters before commands are removed. Unusable derivative caches may be discarded and fetched again; primary commands are removed only after server acknowledgement.

The server validates IDs, ownership, original study times and schedule versions. Each acknowledged command commits independently. A flush captures the pending IDs at its boundary, so an in-flight batch cannot drain a newly started session. Existing review and failure IDs deduplicate replays. Conflicting scheduling commands stay on the device until the user chooses the server schedule; separate mistakes still sync. Choosing the server schedule also clears stale cached predictions. Saving a changed daily limit first flushes pending study, so lowering the cap does not retroactively reject those reviews. Reading and Writing refresh session/difficulty metadata after sync; their explicit Start action waits for pending study acknowledgement and re-reads the session before selecting or generating an exercise. Merely opening either section still makes no AI generation request.

Completion and recovery: the client may show Session Complete only after its complete card response and three valid scoped counters succeed, the active queue is empty, and all three counters are zero. Nonzero counters show Load remaining cards; this session boundary flushes pending commands, reloads normal due/new cards and refreshes counts. Loading, query failures, empty extra-practice responses and pending learning cards have distinct states. Study more waits for pending acknowledgements and consumes its returned result explicitly, including repeated identical responses; failures expose Retry instead of silently retaining a success screen. Extra practice preserves normal schedules until a rating, and cannot bypass the daily new-card allowance.

Category compatibility: the GraphQL and TypeScript LearningContext enums include the stored general_vocabulary, idioms and prepositions labels emitted by the category audit and preserved by reviewed phrase seeding. These metadata values serialize on both word and phrase responses; no existing categories or schedules are rewritten.

studySyncVersion serializes concurrent new-card quota checks within MongoDB transactions. reviewevents.studySessionId and syncedAt retain session provenance; reviewedAt remains the actual practice time.

Short phrase cleanup

scripts/removeShortPhrases.ts audits primary German and Spanish phrase text using Unicode word tokens; punctuation alone does not count and hyphenated/apostrophe words stay together. --apply removes pairs where either language has one to three words. Both phrase documents are removed unless a longer counterpart still belongs to a retained pair. Unpaired short phrases are also removed.

A private EJSON backup precedes a single transaction deleting the selected PHRASES_ES_DE pairs, affected PHRASES_ES/PHRASES_DE documents, all linked PHRASE userprogresses and their reviewevents. Deleted phrase IDs are pulled from TRANSLATIONS_ES_DE.phraseRefs; shared words and surface translations remain. Original ANKI_* archival records stay available for recovery. Count checks and a repeat audit abort the transaction if cleanup is incomplete. This is a catalog cleanup, not a new import validation policy. Existing inventory counts retain their original snapshot date.

Hold a phrase word

A mouse or touch hold opens the popup and automatically sends an authenticated POST /api/word-translations with the actual German tile word, sourceLanguage: de, targetLanguage: es, and the current German phrase as context. The server also supports Spanish → German. Edge punctuation is removed; punctuation-only tiles do not request a translation. The former 500-pair browser dictionary query is removed.

Lookup checks every exact matching vocabulary entry and its valid WORDS_ES_DE relations first, then READY surface translations. German noun entries may include their nominative article. Capitalized noun-only entries do not cover lowercase verbs or other words with a different meaning (for example, Verdienst versus verdienst). No stemming turns an inflection into a lemma. Multiple stored dictionary meanings are returned together. The popup handles loading, visible failure and retry; closing, changing tiles or changing the exercise cancels the browser request and rejects stale results.

Production emergency only

Only a true miss, with NODE_ENV=production, makes one request to the existing server-side GPT Responses client (gpt-6-luna) to translate directly using phrase context and supply grammatical classification, dictionary metadata, examples, contexts and CEFR estimates. Keys stay on the server. The unique index is (sourceLanguage, targetLanguage, key); an expiring 5-minute lease prevents concurrent provider work. Other requests receive 202 PENDING and retry. The client bounds waiting at 5 minutes.

GPT is instructed to keep uncertain classifications and typos out of study vocabulary. Dictionary nouns require correct German capitalization and gender/plural fields; verbs require infinitive spelling plus past, perfect and imperative metadata. Invalid or incomplete generation leaves a FAILED retry record; no incomplete vocabulary pair is exposed. Retry requests a fresh structured GPT result. No intermediate machine translation is stored. Saved emergency surface translations record origin: GPT and the model; manual seed records retain origin: MANUAL. A transaction inserts/enriches dictionary forms plus their Spanish-main/German-translated relation and removes the temporary record, or stores a READY inflected-form translation. Successful lookup thereafter needs no provider call. Closing the popup does not cancel a backend save already running. Dictionary LEXEME transactions invalidate shared study catalog snapshots in finally before session cleanup, including uncertain commits or cleanup failures; SURFACE-only saves leave those snapshots intact. The separate Writing contextual-hint flow is unchanged.

Reviewed phrase seed

scripts/seedPhraseTranslations.ts audits every primary PHRASES_ES and PHRASES_DE phrase into an ordered token list and a deduplicated word index with occurrence IDs. Synonyms are alternate answers, not bank sources. Manual JSON covers all missing tokens; every occurrence is checked, preserving German noun capitalization, and schema and complete-coverage checks run before writes. No LibreTranslate or external GPT request runs during seeding.

Pure dictionary forms reuse and fill suitable word entries or create full vocabulary documents, both-language forms, examples, contexts, CEFR estimates and a WORDS_ES_DE relation. Source phrases gain a words[] reference if required. Inflections, plurals, contractions and names go to TRANSLATIONS_ES_DE, with morphology, phrase references and optional existing lemma IDs. Historic autogenerated UNKNOWN word records and their phrase/progress references are preserved. New dictionary entries become study cards, so only reviewed source and target dictionary forms are admitted; uncertain or ambiguous forms stay in translations. Re-running the seed is idempotent; writes are transactional per entry. A final pass links surfaces to verified lemmas added later. A separately reviewed repair replaces one pre-existing dangling phrase-word ID only after checking the exact phrase and its verified replacement. Missing related-word containers on reviewed legacy dictionary entries are completed with empty arrays; existing custom study-category labels are retained. Final read-only verification checks every token, word-pair and phrase reference, and metadata on new or repaired study words.
