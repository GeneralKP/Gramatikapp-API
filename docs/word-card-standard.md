# Stored German word-card standard

Audit date: **2026-10-08**. This adapts the owner's supplied Spanish Anki prompt to plain-text structured storage. The audit runner produces local linguistic **drafts** and cannot apply production changes; it does not assert external-source verification of every word. The owner separately authorizes the corrections described below. See [the linguistic research and limitations](word-card-prompt-research.md).

## Canonical study content and dictionary identity

A German study front identifies one actual construction and intended sense. Nouns normally include their verified article; verb fronts use the infinitive and visible complement case. Countries and continents follow their established article conventions; personal names do not acquire an article. A plural front such as `Die Häuser` does not establish feminine singular gender. Pronouns and function words retain the actual required forms.

The study front is distinct from the stored dictionary lemma or surface token used in phrase explanations and exact dictionary lookup. A seed token such as `steht` can receive a draft front `stehen` without renaming the underlying token or automatically allocating another duplicate study pair. Catalog IDs, relation IDs, phrase references, directional identity, schedules, mistakes and archived imports are preserved. Related candidates and canonicalized seed fronts require whole-catalog construction-and-sense deduplication before any creation.

The locally prepared dictionary reader uses valid version-1 pair content for the existing German/Spanish `Word.word` response and German notes, including empty notes. Valid optional German/Spanish pair example arrays supply the displayed meaning’s language-specific examples; older or malformed optional arrays fall back to source examples. Intentionally empty arrays remain empty. CEFR metadata and document IDs retain their original roles. Valid optional pair forms/category supply German grammar for the displayed construction, with source grammar as the older-content fallback; Spanish grammar remains source-owned. Bilingual search accepts both the reviewed construction and the stored lookup spelling; word pagination sorts by the visible German label and relation ID. Invalid or legacy pair content retains the original response. GraphQL projection carries the four base study fields, optional forms/category only when selected German grammar needs them, and each language’s optional example array only when its existing examples field is requested. Bilingual study examples are not loaded by the dictionary, and no additional query is added. Web and native clients keep the same operations. Web Apollo embeds Word responses under their parent/query context to preserve distinct reviewed cues sharing a stored ID; native page caches already retain those nested responses separately. This API reader and browser cache policy require an explicit deployment instruction before they change production behavior.

All existing Spanish relations remain present with their exact IDs and intended sense. Synonymous translations can share a construction; incompatible senses require a reviewed split. Such drafts use `needs_review` and an explicit `incompatible_senses: cannot_auto_apply` issue. A single primary German example array is a limitation for unresolved multi-sense records: paired Spanish sentences translate those German sentences accurately, while the preserved incompatible Spanish front remains a review blocker. Do not auto-apply such a draft.

Migration gate correction, 8 October 2026: `cannot_auto_apply` blocks when it starts an issue, optionally after an issue key such as `incompatible_senses:`. Explanatory prose quoting a removed blocker does not reactivate it. High confidence, relation-specific variants and all required companion proofs remain independently necessary; an explicit active marker still blocks even when another issue describes a resolution. Frozen reviews remain unchanged.

The second review pass extends each translation with a required `variant` containing German front, category, forms, notes, German examples and confidence/review reason. Its Spanish example array pairs with that variant's German array. Different existing relations can therefore retain distinct valid constructions without giving every relation the primary German front. The primary fields remain available for shared lexical metadata. When a noun correction changes the lexical head, the migration preserves original phrase-lookup grammar and the primary translation link. Reviewed pair forms/category hold the corrected construction’s grammar without assigning another noun’s gender or plural to the lookup word. Matching noun heads, governed noun complements and explicitly reviewed same-lemma plurals can still update coherent shared metadata. Secondary relation-specific variants still use separate coherent records. Their lookup spelling stays the original token when the reviewed noun head or final verb lemma matches; the full study construction remains in the pair. A different lexical head receives its canonical spelling, preserving every original primary translation link. A single Spanish relation combining several useful senses still requires a companion card: candidates use `split_existing_sense` reasons and `split_requires_companion_card` issues, and the primary card must not be narrowed until its companion has been generated, reviewed and included in the migration. The dictionary gloss stays separate.

## Plain text and allowed display annotations

Keep structured JSON fields. Notes use real newlines; examples use separate strings. Never store HTML, `<br>`, TSV records, serialized arrays or embedded numbering. Both clients number example arrays at display time. German and Spanish example arrays are aligned by position, normally two sentences; personal reflexives can have a third only for a genuine useful nonreflexive use. Excluded nonlexical drafts can have empty paired arrays. The owner's §9.1 allows real, current standard German words, constructions and meanings; a proper name alone is not a blanket exclusion. A useful named construction still requires an actual independent review of its German usage and complete paired card.

Imported live WORD cards can receive a format-only numbering cleanup even while their meaning is held: remove leading `1) `, `2) ` and subsequent markers only when the entire example array matches its exact ordered indices. Preserve every sentence and bilingual pairing. Mixed or reordered arrays, date-like full-stop prefixes and unproven separators remain untouched. Complete reviewed content takes precedence when available. The private manifest retains exact prior examples for rollback; no other card field, identity or schedule changes through this cleanup.

The only special visible annotations are:

| Annotation | Location |
| --- | --- |
| `(rflxv.)` | Spanish front when German is reflexive and the Spanish translation is not pronominal |
| `(formal)` | Spanish front for a common formal-register variant |
| `Reflexiv: Dativ (mir/dir)` | Final notes line for a personal dative-reflexive construction |
| `Komparativ: …, am …` | Notes for an actual comparison form |
| `Redewendung` | Idiom notes, taking precedence over conjugation notes |

Internal category, gender and construction case metadata remain allowed. Visible tense, category, gender and rarity labels, generic dictionary-review text, and negative availability explanations are removed. Unknown or unavailable forms are empty strings.

Noun notes contain only the `Die …` plural line, or are empty for mass nouns and existing plural fronts. Verb notes equal the nonempty perfect, past and imperative form fields in that order, followed where appropriate by the exact dative-reflexive line. Perfect forms include their sense-specific auxiliary; past forms normally include `ich`, with a natural third-person form for the intended construction or reciprocal `wir` where appropriate. Follow the supplied prompt's ordinary same-sense usage criterion: omit an imperative that has no useful real use in that construction, without falsely declaring every imaginative personal or metaphorical form grammatically impossible. An unusual command alone does not establish unavailability (`stoß zusammen!, stoßt zusammen!`). A dictionary conjugation table establishes morphology; examples must still demonstrate the intended meaning. Ordinary collocation notes conjugate only the verb, including fragmentary `hab!, habt!` for `Spaß haben`; reflexive notes retain the pronoun and identifying accusative object. Reciprocal dative constructions can take `sein`; the copular adjective construction `sich einer Gefahr bewusst sein` also retains `sein` with a dative reflexive and genitive content. Modal perfects and vehicle-driving senses require their own construction checks. These corrections to the supplied prompt are documented in the research. This final review policy does not rewrite the hash-bound instructions or previously saved checkpoints; controlled independent reconsideration records any resulting changes.

Complement slots use one actual placeholder each. Spanish fronts preserve the order of German complements, with the Spanish verb last; idioms and fixed `es` expressions use natural Spanish. No slash alternatives. Reflexive pronoun case must be verified for the complete construction rather than guessed from a second object alone.

## Private snapshot audit runner

`scripts/auditWordCards.ts` reads the dated BSON EJSON snapshot only. It opens no database connection and cannot apply corrections. Only German lexical fields, Spanish lexical fields and live-card text enter the provider request; owner IDs, progress IDs, schedules and other user data are omitted. Identical live-card text is deduplicated across owners.

The runner uses the configured `OPENAI_API_KEY` and optional `OPENAI_BASE_URL`, the Responses API, `gpt-6.1-sol`, high reasoning, `store: false`, and a strict structured output schema. The default batch size is 16, concurrency is capped at 3, output cap is 24,000 tokens, and request timeout is 240 seconds. Each batch has at most three attempts; quota exhaustion stops the run and aborts other in-flight requests. Provider bodies and transport errors are never printed. Successful batch and per-entry checkpoints are written atomically with file mode `0600` inside private `0700` directories. Source, input, prompt and model hashes determine whether existing per-entry checkpoints can resume.

Using the project's Node runtime:

```sh
PATH=/Users/kevin/.nvm/versions/node/v24.18.0/bin:$PATH node_modules/.bin/tsx scripts/auditWordCards.ts --self-test
PATH=/Users/kevin/.nvm/versions/node/v24.18.0/bin:$PATH node_modules/.bin/tsx scripts/auditWordCards.ts --limit 12 --batch-size 12 --concurrency 1
PATH=/Users/kevin/.nvm/versions/node/v24.18.0/bin:$PATH node_modules/.bin/tsx scripts/auditWordCards.ts
PATH=/Users/kevin/.nvm/versions/node/v24.18.0/bin:$PATH node_modules/.bin/tsx scripts/auditWordCards.ts --review
PATH=/Users/kevin/.nvm/versions/node/v24.18.0/bin:$PATH node_modules/.bin/tsx scripts/auditWordCards.ts --validate-only
```

`--snapshot PATH`, `--output DIR`, `--offset N`, `--limit N`, `--batch-size N`, `--concurrency N`, `--model NAME`, `--timeout-ms N`, `--max-output-tokens N` and `--attempts N` support a pilot, bounded reruns and explicit configuration. A full run resumes a valid pilot even when the batch size changes. `--review` requires valid first-pass checkpoints for the selected scope, sends each original entry with its fallible first-pass draft for an independent semantic critique, and saves separate resumable results in `review/`. Review input hashes also include the first-pass draft. Combine `--review --validate-only` to validate those checkpoints offline. Aggregate `drafts.json` and `summary.json` describe the selected scope; individual checkpoints retain successful drafts across failures. Files contain sensitive catalog/card content and remain local and ignored by Git.

Mechanical validation checks exact ID coverage, relation identities/count, string form fields, no HTML or embedded numbering, allowed notes, article/gender consistency without assuming plural `Die` is feminine, verb notes assembled from forms, aligned example counts, sentence capitalization and terminal punctuation (including closing quotation marks). It **cannot prove** valency, intended-sense preservation, example translation quality, lexical gender or contemporary frequency. Uncertain linguistic drafts must stay in the review queue.

When the configured audit API exhausts its quota, `agentWordCardAudit.ts` can prepare offline lexical jobs for the authorized GPT-6.1 Codex team. The actual agents perform the linguistic work at high/xhigh effort; this is not a template generator or a quota retry. Intake verifies the exact source, first-pass draft, prompt and strict schema before writing private checkpoints. Each result records its actual agent, effort and job/result hashes. Existing valid checkpoints stay intact, and an agent cannot second-review its own first-pass card. The ordinary runner's offline validation rebuilds complete aggregates from both execution methods. After controlled final reconsideration, freeze the complete review aggregate once and retain its checksum. Addition proposals and every later helper proof must bind those exact bytes; regenerating aggregate timestamps requires new proposals and proofs. `agentWordCardHelpers.ts` extends actual-agent intake to construction-and-sense deduplication, original answer alternatives and new-entry CEFR estimates. It rebuilds lexical jobs from the complete original source artifacts, records actual agent/effort and job/result hashes, refuses stale checkpoint replacement and makes no provider or database request. The existing helper validators assemble the final source-bound proofs offline.

Explicit final intake adds `--reconsider` to `--ingest --review`. Its prepared lexical job additionally binds the approved reconsideration plan, source-check files and exact earlier-review checksums. The actual final reviewer must differ from both earlier agent authors. The complete result and every source binding must validate before any review is reopened. Earlier bytes are retained in private checksum-named history, and a local job journal records the replacement. Stale evidence, invalid content and repeated intake with an obsolete prior checksum are refused. The plan identifies the future frozen aggregate; reconsideration refuses once that file exists. An interrupted intake requires inspection of its saved reviews and journal before continuing. Close the reconsideration plan when freezing the final aggregate; ordinary intake continues to preserve valid checkpoints.

The category enum has no numeral member. The nine source-checked lowercase cardinal spellings `zehn`, `drei`, `fünf`, `vier`, `sechzig`, `zwei`, `acht`, `sieben` and `neunzig` can retain `UNKNOWN` after a high, study-eligible independent review when notes and all seven actual form fields are empty. This does not admit digits, capitalized numeral nouns, ordinal/compound phrases or other meanings of `sieben`; see the separate source ledger.

The complete source review was frozen on **8 October 2026 at 05:53 UTC** after both passes covered all **3,988 German entries**, with **0 invalid checkpoints**. The second pass records **3,957 high-confidence entries** and **31 held entries**; this is semantic-review coverage, not a claim that every entry has a fresh external dictionary citation. Held original meanings remain unchanged. The private aggregate and checkpoint checksums are fixed before addition and accepted-answer decisions.

Related candidates are bounded to four clear common constructions per entry: useful separable-family members, common formal equivalents, modern homograph senses, reflexive/person-versus-thing constructions and meaningful noun/verb pairs. They are suggestions to check against all catalog entries, not an exhaustive derivative generator or proof a card is absent. New-card queue spacing requires separate scheduler verification.

## Companions, answer alternatives and production corrections

The owner has authorized corrections and justified missing vocabulary for this audit. The snapshot runners themselves perform no database writes. Production application uses a separately built reversible manifest, exact stale-value checks and private recovery journals. Existing word spellings, relation endpoints and live-card identity are guarded alongside touched lexical values; concurrent schedule updates are permitted and never replaced by the content migration.

Migration preflight overlaps at most eight read-only inspections per batch and waits for every inspection in that batch to settle before returning or rejecting. Conflicts retain manifest order in the private journal; any known conflict prevents all writes. This is not an atomic database snapshot. Preflight may validate a relation against a planned word insert; actual relation operations must read both stored endpoints. Each subsequent write remains sequential, checks current values and relation references again, and records its durable journal entry before the compare-and-set operation. These reference reads are point-in-time checks, not atomic foreign keys.

Rollback of a manifest containing inserts requires every catalog/reference writer to be paused for the whole operation. The CLI requires `--writers-paused-for-rollback`, and the migration library requires `writersPausedForRollback: true`, before any rollback read or write. The acknowledgement does not pause writers or establish a shared lock; the operator must establish quiescence first. Owned isolated fixtures have a single writer and can explicitly satisfy this precondition. Existing-reference checks and document compare-and-set deletion remain additional guards. Patch-only rollback retains its field-level concurrency checks.

`prepareWordCardAdditions.ts` proposes additions from the complete independent review only. A sense key retains the proposal's actual reason or an unlinked entry's own reviewed forms and examples. Matching front text is not proof of matching meaning: `Die Bank / el banco` can identify financial `Banken` or seating `Bänke`. Every existing-front or peer collision goes through `reviewWordCardCandidates.ts`. Its decisions bind to the exact source and review bytes and can cover only actual existing relations or lower-ID peer representatives. Internal case metadata normalizes a plain case label and an explanation naming the exact same construction, optionally with its matching person-case pronoun. Colon and plus separators also normalize only when the literal governing token and single case label agree. Semicolon and plus separators between two exact ordered case labels retain both complement cases; alternatives such as “oder”, changed cases and other prose stay exact. Different cases, prepositions, other lexical contexts and absent required evidence remain blocked; this format check never decides semantic equivalence. Duden-checked singular imperative alternatives normalize only for thirteen exact constructions: `etwas ablehnen`, `etwas bauen`, `etwas einhalten`, `etwas feststellen`, `etwas fühlen`, `etwas schaffen`, `etwas umsetzen`, `etwas verlieren`, `etwas vortäuschen`, `etwas zeigen`, `jemandem etwas erzählen`, `jemandem etwas mitteilen` and `lachen`. Each allowance binds the complete short/long singular forms, unchanged plural and particle; there is no generic suffix deletion. Strong/weak `schaffen` past and perfect forms remain distinct. For the exact construction `etwas tun können`, accusative-object and bare-modal-infinitive descriptors describe complementary grammatical layers; no other construction or case uses that allowance. The exact factual construction `etwas wissen` retains explicit accusative evidence when its descriptor also names an `Inhaltssatz`; `wissen + zu` ability and different cases remain excluded. The exact monetary construction `Geld kosten` retains accusative evidence when its explanation names the money amount; tasting and different cases remain exact. Irregular person lists accept comma or semicolon delimiters, exact requested-person subsets and an explicit `er/sie/es` group. Conflicting or duplicate person forms, unknown prose, changed conjugations and missing required evidence remain blocked. None of these comparisons decides the intended meaning. `finalizeWordCardAdditions.ts` verifies that graph and emits missing representatives for generation and another independent review; covered aliases remain explicit proofs. No recursive family expansion occurs.

An approved grammar or metadata correction can preserve meaning without rewriting any frozen proposal or checkpoint. Changed or uncertain intentions remain held. Existing same-meaning coverage uses only a provided ready relation; final peer aliases use a lower-ID representative whose own decision is complete and usable. The compiler rechecks current migration eligibility for that existing relation or representative. These final decisions cannot bypass confidence, active blockers, unresolved answer alternatives or required companion checks. The offline `final` helper stage records complete source-bound actual-agent decisions before compilation; it makes no database/provider call. Omitting the final flags cannot replace an existing output.
